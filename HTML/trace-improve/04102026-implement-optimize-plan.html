Expo / React Native Phase 0 — งานบล็อก Phase 1 — ฟีเจอร์ pnpm
เป้าหมาย: ส่งมอบฟีเจอร์ที่เลือกไว้ และแก้ปัญหาเครื่องค้าง (freeze) — โดยแก้ปัญหา freeze ก่อน

1 วินิจฉัยสาเหตุเครื่องค้าง (หลักฐาน)

  1. หน้า History เรนเดอร์ session ทั้งหมด ใน ScrollView โดยมี Reveal + Animated.timing หนึ่งชุดต่อหนึ่งแถว (App.tsx:401-421) เมื่อมีหลายร้อยแถว = view tree ขนาดใหญ่มาก + timer ที่ยังค้างอยู่หลายร้อยตัว หลักนี่คือสาเหตุหลักที่ทำให้ค้าง
  2. เวลาหน่วงต่อแถว (stagger) ไม่มีขอบเขตสูงสุด: delay={groupIndex*70+90+index*40} (App.tsx:406) → 500 แถว = ท้ายคิว timer ยาว 20 วินาที
  3. ฝั่ง native สร้าง SimpleDateFormat ใหม่ทุก session (UsageAccessModule.kt:82) ช้าและสิ้นเปลือง
  4. ฝั่ง native เรียก PackageManager.getApplicationInfo ทุก session (UsageAccessModule.kt:77) = IPC ต่อหนึ่งแถว และไม่มี cache
  5. ไม่มี package blocklist → event ของ launcher / system (com.nothing.launcher, com.android.systemui) กลายเป็น session ทำให้มีทั้ง noise และปริมาณที่เกินจำเป็น
  6. ไม่จำกัดจำนวน session ที่ส่งกลับ การ query ทั้งวันอาจได้หลายพันแถวผ่าน bridge แล้ว JSON.stringify + เขียนลง AsyncStorage (lib/usage.ts:20) ทำให้ JS ค้าง
  7. totalSeconds ถูกคำนวณใหม่ทุก render และ summaries ถูกจัดเรียงใหม่ทุก keystroke (App.tsx:146-147) ผลกระทบเล็ก
  8. การ refresh ไม่มี concurrency guard → แตะเร็ว 2 ครั้ง = native query และ write ซ้อนกัน 2 ชุด (App.tsx:114-136)

2 Phase 0 — แก้ปัญหาเครื่องค้าง ทำก่อน / บล็อกการทดสอบบนเครื่องจริง

  1. History: เลิกใช้ Reveal รายแถว เปลี่ยนเป็น static rows เมื่อ items.length > 50 และจำกัด stagger เป็น Math.min(index,12)*45
  2. History: ใช้การ virtualize ด้วย FlatList (initialNumToRender={30}, windowSize={7}, maxToRenderPerBatch={20}) โดยเก็บ group header ไว้ผ่าน SectionList
  3. Today / Apps: แสดง 20 แถวบนสุด + ปุ่ม "ดูทั้งหมด" และจำกัด stagger ตามกฎเดียวกัน
  4. Native: ย้าย SimpleDateFormat ไปเป็น instance ระดับ class และ cache ค่า label ไว้ใน MutableMap<String,String>
  5. Native: เพิ่ม blocklist setOf(ownPackage, "com.nothing.launcher", "com.android.systemui", "com.android.launcher3", "com.sec.android.app.launcher") โดยทำเป็น const ที่ตั้งค่าได้
  6. Native: จำกัดผลลัพธ์ไม่เกิน 2000 sessions (ตัด session ที่สั้นที่สุดหรือเก่าที่สุดออกก่อน และระบุเหตุผลที่เลือก)
  7. JS: เพิ่ม guard ด้วย refreshing ที่ต้นฟังก์ชัน refreshRealUsage และปิดปุ่มระหว่าง refresh
  8. JS: memoize ค่า totalSeconds ด้วย useMemo
  9. ทดสอบบนเครื่องจริง: เปิด History เลื่อนเร็ว แล้วสลับแท็บ → เกณฑ์ผ่าน = ไม่มี ANR และเลื่อนลื่นตลอด 60 วินาที

3 Phase 1 — ฟีเจอร์ที่เลือก

Today

  1. เทียบกับเมื่อวาน: badge +/- % สีเขียว/แดง อยู่ใต้ตัวเลขหลัก
  2. กราฟแท่งขนาดเล็ก 7 วัน (sparkline): วาดด้วย View (ไม่เพิ่ม dependency) ดึงข้อมูลจาก sessions ที่จัดกลุ่มตามวัน
  3. แยกหมวดหมู่: map categoryOf(packageName) (Social / Games / Productivity / Other) + แถบสัดส่วนแนวนอนด้วยอัตราส่วน flex
  4. การ์ด insight: ข้อความสั้นหนึ่งบรรทัดจากหมวดที่เปลี่ยนแปลงมากที่สุด (เช่น "Social 45 นาที, +22% เทียบเมื่อวาน")

Apps

  1. หน้า detail: แตะที่แถวเพื่อเปิดรายละเอียด (รายการ session, แนวโน้มรายวัน, ระยะเวลาเฉลี่ย) ใช้ state ใหม่ selectedApp ไม่ใช้ router
  2. หมวดหมู่: ตรวจจับอัตโนมัติจาก keyword map ของชื่อแพ็กเกจ/ชื่อแอป + ตั้งค่าเองได้ เก็บค่าไว้ใน AsyncStorage
  3. แนวโน้มรายสัปดาห์: sparkline 7 วันแยกรายแอป + badge ขึ้น/ลง
  4. ค้นหาและเรียงลำดับ: ช่องค้นหา + โหมดเรียง (เวลาที่ใช้ / จำนวนครั้งที่เปิด / ชื่อ / เปิดล่าสุด)
  5. ไอคอนจริง: ลองใช้ icon API ของ expo-application หากไม่ได้ให้ fallback เป็นตัวอักษรแรก (แบบเดิม)

History

  1. แท็บ Calendar dashboard: ตารางเดือน โดยแต่ละช่อง = ยอดรวม + จำนวนแอป + แถบสัดส่วน แตะที่วันเพื่อเปิดแผงรายละเอียด (ใช้สเปกจาก HTML mockup เดิม)
  2. เลื่อนเดือน + ปุ่ม "กลับไปวันนี้"
  3. ตัวเลือกวันที่: ใช้ DateTimePicker เมื่อจำเป็นเท่านั้น dependency ใหม่(@react-native-community/datetimepicker ใช้เฉพาะ Android)
  4. Timeline 24 ชั่วโมง: แถบแนวนอนใช้อัตราส่วน flex สีตามแอป แตะที่ช่วงเพื่อดูรายละเอียด session
  5. รายละเอียด session: แผงแบบ bottom sheet พร้อมเวลาเริ่ม/สิ้นสุดที่แน่นอน + ลิงก์ไปหน้ารายละเอียดของแอป
  6. การ์ดสรุปรายวัน: ยอดรวม, จำนวนแอป, 3 แอปที่ใช้เวลามากที่สุด

Settings

  1. Dark mode: ใช้ useColorScheme + theme const และเก็บค่าที่เลือกไว้ใน AsyncStorage
  2. Notifications: ใช้ expo-notifications dependency ใหม่สำหรับสรุปรายวัน + แจ้งเตือนเมื่อใช้เวลาเกินลิมิต
  3. Retention: 7 / 30 / 90 วัน หรือไม่จำกัด และตัดข้อมูลตอนโหลดแอป
  4. สลับภาษา TH/EN: ใช้ตารางข้อความ และเก็บค่าไว้
  5. หน้า Debug: จำนวน raw event, จำนวน session, ขนาดที่ใช้ใน storage, เวลาที่ query ล่าสุด

4 การตรวจสอบ (Verify)

  • pnpm exec tsc --noEmit (ต้องจบด้วย exit code 0)
  • เช็กลิสต์ทดสอบบนเครื่องจริง: เปิดแอปครั้งแรกน้อยกว่า 3 วินาที, เลื่อน History แล้วไม่ค้าง, refresh เร็ว 2 ครั้งติด, airplane mode, กรณีผู้ใช้ปฏิเสธสิทธิ์
  • PROJECT_ROADMAP_AND_STATUS.md: อัปเดต Change History ทุกครั้งที่มีการเปลี่ยนแปลง

5 ความเสี่ยง / คำถามที่ยังค้าง

  • ความครอบคลุมของ icon API ใน expo-application บน Nothing OS: ต้องทดสอบจริง โดยมีค่า fallback ไว้แล้ว
  • ขั้นตอนการขอ permission ของ notification บน Android 13+: ขอ ณ ตอนที่ผู้ใช้เปิดใช้งานในหน้า settings
  • Dark mode เพิ่มงาน QA เป็นสองเท่า: รวมธีมไว้ที่ colors จุดเดียว ห้ามแยก style รายหน้าจอ
