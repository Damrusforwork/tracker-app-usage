ข้อจำกัดหน้าความเป็นส่วนตัวบอกว่าเป็น event เปิด–ปิดแอป, แบ่งจอ/PiP อาจนับซ้อน, บางยี่ห้อตัด event เว็บมีข้อความว่าอ่าน Usage Access ไม่ได้

ควรปรับ — ลงโค้ดแล้ว

  • ประวัติแบ่ง session ที่คร่อมชั่วโมงตามสัดส่วนเวลาที่นับได้
  • event เปิดซ้ำก่อนปิด จะปิดช่วงแรกไว้ ไม่ทับหาย
  • นับแอป foreground ได้ทีละแอป แบ่งจอหรือ PiP ไม่ถูกนับซ้อน
  • Session ที่ยังเปิดอยู่ใช้ id ลงท้าย -live รีเฟรชแล้วแทนที่แถวเดิม
  • แท็บแอปเลือก วันนี้ / 7 วัน / 30 วัน
  • มีหมวดการเงินและสื่อ สำหรับธนาคาร เพลง กล้อง
  • เอาแผงดีบักออกจากหน้าตั้งค่า

ยังไม่เปลี่ยน package com.anonymous.appusagetracker และ debug keystore จนกว่าจะมีชื่อแอปและคีย์ของเจ้าของโปรเจกต์

ควรเพิ่ม — ลงโค้ดแล้ว

  • ช่วงเวลาในแท็บแอปตรงกับหน้ารายละเอียด
  • หน้ารายละเอียดกดไม่นับแอปนี้ หน้าตั้งค่ากดเพื่อนับกลับ
  • เลือกหมวดเองแล้วจำบนเครื่อง
  • ค้นหาในประวัติ ตามคำอธิบายด้านล่าง
  • เป้าวันนี้ 1/2/4/6 ชม. แสดงแถบบนหน้าวันนี้ ไม่แจ้งเตือน

กรองประวัติตามแอป

ช่องค้นหาบนหน้าประวัติเทียบชื่อแอปและ package รายการที่เหลือถูกจัดกล่องวันและชั่วโมงใหม่ ยอดชั่วโมงจึงเป็นของแอปที่ค้นเท่านั้น เคลียร์ช่องค้นหาแล้วประวัติทั้งหมดกลับมา ข้อมูลในเครื่องไม่ถูกลบ

ยังไม่ควรเพิ่ม

  • Cloud sync, export และ Accessibility Service ขัดกับที่ตัดสินใจไว้แล้ว

ตอนทดสอบบนเครื่อง

  • ติดตั้งหรือ rebuild หลังแก้ Kotlin แล้วเปิด Usage Access
  • วันติดตั้งควรเห็นวันก่อนหน้าในปฏิทิน ถ้า Android ยังเก็บ event อยู่
  • เปิด YouTube หรือ LINE แล้วล็อกจอ เวลารวมต้องไม่กินช่วงล็อกจอ แม้จะรีเฟรชซ้ำ
  • สลับออกแล้วกลับเข้า TRACE ตัวเลขควรอัปเดตโดยไม่ต้องกดรีเฟรช
  • แถวแอปกับหน้ารายละเอียดต้องเป็นยอดช่วงเดียวกัน
  • ไม่มีแถบเขียวที่เต็มหลังใช้ไม่กี่นาที และไม่มีสวิตช์แจ้งเตือน 21:00
